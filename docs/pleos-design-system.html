Pleos Design
System

Pleos Connect 공식 화면 목업의 생김새를 따르면서, 주행 중 2초 안에 읽히도록 규칙을 더한 차량용 앱 디자인 시스템입니다.

Pleos Design System v2는 Pleos Connect(현대자동차그룹 차량용 OS) 위에서 Vehicle SDK로 차량 데이터를 다루는 앱을 위한 UI 시스템입니다. v2는 Pleos Connect 공식 화면 목업(주행 중·정차 중 2장)을 기준으로 색, 표면, 그림자, 앱 아이콘, 화면 구조를 다시 만들었습니다.

출처와 가정 · 화면 구조(상태바 · 드라이빙 뷰 · 앱 윈도우 최대 2개 · 하단 독)와 생김새는 공식 목업에서, 주행 규제·화면 방향·SDK 규칙은 Pleos 개발자 문서에서 가져왔습니다. 색 값은 목업 스크린샷에서 뽑은 근사값을 대비 기준에 맞게 조정한 것이며 공식 System Color가 아닙니다. 공식 값이 생기면 토큰만 바꾸면 컴포넌트는 그대로 따라옵니다. 드라이빙 뷰의 차량 이미지는 공식 목업 캡처를 그대로 썼고(Day), Night에서는 같은 이미지의 배경을 지워 씁니다. 현대자동차그룹·Pleos 로고와 공식 앱 아이콘은 포함하지 않았습니다.

화면 구조

Pleos Connect 화면은 네 영역으로 나뉩니다. 앱이 그릴 수 있는 곳은 앱 윈도우뿐이고, 나머지는 시스템이 그립니다.

기어
앱 윈도우
① 상태바속도 · 기어(P/D) · 주행가능거리와 배터리 · 검색 · 알림 · 통신 상태 · 프로필 · 시계. 앱은 이 정보를 중복해서 그리지 않습니다.
② 드라이빙 뷰운전자 쪽에 고정. 주행 중에는 차로와 내 차, 정차 중에는 차량 모델과 빠른 조작. 앱이 가리거나 닫을 수 없습니다.
③ 앱 윈도우최대 2개. 분할이면 앱마다 Portrait 윈도우 1개, 전체면 앱 하나가 두 윈도우를 함께 씁니다. 사용자가 위치·크기를 바꿀 수 있습니다.
④ 독공조(온도·바람·시트) · 고정 앱 아이콘 · 실행 중인 앱(점 표시) · Gleo AI. 앱 아이콘은 여기에 그라디언트 사각형으로 놓입니다.

원칙과 규칙

1. 디자인 원칙

2초 안에 읽힌다. 한 화면에 핵심 수치 하나(display-xl) 또는 카드 4개 이하. 나머지는 다음 화면으로 보냅니다.

한 손, 한 번의 탭. 터치 타깃은 touch-min(76) 이상, 주행 중 주요 액션은 touch-lg(96), 간격 16 이상. 드래그·슬라이더·멀티 터치 금지(Stepper 사용).

주행 중엔 줄어든다, 사라지지 않는다. 제한 기능은 숨기지 않고 🔒로 잠그고, RestrictionBanner 한 줄로 이유와 해제 조건을 말합니다.

움직이지 않는다. 자동 애니메이션·자동 스크롤·숫자 카운트업 금지. 연출은 정차(P) 중에만.

반응은 즉시, 기다림은 보인다. 탭 후 0.25초 안에 눌림 표시, SDK 응답이 늦으면 loading.

시스템과 한 화면처럼. 목업의 표면·그림자·모서리·아이콘 문법을 따라, 앱이 지도·미디어 윈도우 옆에 놓여도 이질감이 없게 합니다.

3. 콘텐츠 원칙

  • 해요체, 짧게. 문단 3줄 이하, 한 줄 영문 기준 80자 이하.
  • 무엇이 일어났는지 → 무엇을 하면 되는지. 예: "정보를 가져오지 못했어요 · 다시 시도"
  • 숫자와 단위를 분리하고 단위는 작게: 86 %, 440 km.
  • 제한 문구에는 해제 조건을 함께: "정차하면 이어서 볼 수 있어요".
  • 알림·토스트에 광고 문구 금지.

앱 패턴

프로토타입 8종을 만들며 정한 규칙입니다. 새 앱도 이 패턴을 먼저 고르고 시작합니다.

P1. 주행 화면 = 핵심 하나 + 행동 둘

  • AppBar 아래 RestrictionBanner, 그 아래 상태 카드 하나(display-xl 수치 또는 한 문장), 맨 아래 lg 버튼 2개(왼쪽 secondary, 오른쪽 primary).
  • Portrait(분할)에서는 제목·버튼 라벨을 줄이고(예: "가장 가까운 쉼터 안내" → "가까운 쉼터"), 보조 카드는 숨깁니다.
  • 목록은 주행 중 2개, Portrait 주행 중 1개까지.

P2. 경고는 단계로, Dialog 없이

  • 양호(positive) → 주의(caution, TTS 1회) → 경고(critical, 경고음+TTS) → 위험(critical 전면, 반복 안내). 같은 레이아웃에서 색·아이콘·문구만 바뀝니다.
  • 운전자가 시작하지 않은 Dialog는 띄우지 않습니다. 화면 상태 전환 + 소리로만 알립니다.
  • "괜찮아요"는 일정 시간(예: 10분) 뒤 다시 확인. 같은 안내는 최소 간격을 둡니다.

P3. 정차 전용으로 미루는 것

  • 연출(도장, 해금 애니메이션), 상세 리포트·그래프, 설정 변경, 목록 전체, QR 연결, 텍스트 입력.
  • 주행 중 눌린 차량 제어(예: 조명 색)는 보류했다가 정차하면 반영하고 Toast로 알립니다.
  • P단 전환을 트리거로 쓸 때는 AAOS GEAR_SELECTION을 구독합니다.

P4. 듣는 운전자, 입력하는 동승자

  • 입력이 필요한 기능은 동승자 기기(QR로 여는 모바일 웹, 주행 규제 없음)로 보냅니다. QR은 정차 중에만 표시.
  • 운전석은 TTS로 읽고, 답은 프리셋 1탭 또는 STT. 메시지는 최신 1개 + "외 n개".

P5. 길 안내는 시스템 내비에 맡긴다

  • 앱은 지도를 직접 그리지 않고 NaviHelper로 목적지·경유지를 넣습니다. 분할 화면에서는 옆 지도 윈도우가 그 경로를 보여 줍니다.
  • 도착은 onDestinationArrived / onWayPointArrived를 1차로, FusedLocation addProximityAlert를 보조로.

P6. 확인된 API만으로 완결 (1층/2층)

  • 1층: 문서에서 메서드를 확인한 API만으로 핵심 기능이 동작해야 합니다.
  • 2층: 미확인·제휴 필요 기능(카메라, 차량 졸음 경고, 블루멤버스 등)은 Capability가 있을 때만 켜지는 확장으로 둡니다.
  • 미지원 차량에서는 StatCard unavailable 또는 토글 비활성 + 이유 한 줄.

P7. 동의 화면

  • "저장하는 것 / 저장하지 않는 것 / 알아 두세요" 3행 리스트 + 거절·동의 버튼. 거절해도 핵심 기능은 동작하고 일부(포인트, 개인 예측)만 제한.

P8. 시스템과 같은 표면

  • 앱 윈도우 shadow-win, 카드 shadow-1, 떠 있는 컨트롤 shadow-2. 앱 아이콘은 28% 둥근 사각 + 그라디언트 + 같은 색 계열 테두리 글로우 + shadow-icon.
  • 첫 화면 AppBar는 앱 아이콘 + 제목. 실행 중인 앱은 독에서 아이콘 아래 점으로 표시됩니다.
  • 몰입형 화면(미디어, 사진 복기)만 Immersive 윈도우.
